### **正确的流程**

1. **模型制作阶段**：
    - 在模型制作阶段（例如使用 Blender 或其他 3D 建模工具），GLTF 模型可以被导出为 Draco 压缩格式。
    - 这意味着模型的几何数据（如顶点、法线、UV 等）已经被 Draco 算法压缩，文件大小显著减小。

2. **网络传输阶段**：
    - 压缩后的 GLTF 文件通过网络传输到客户端（浏览器或应用程序）。
    - 由于文件大小更小，传输时间更短。

3. **客户端解压缩阶段**：
    - 客户端接收到压缩后的 GLTF 文件后，需要使用 Draco 解码器对其进行解压缩。
    - 解压缩后的数据会被传递给 WebGL 或其他渲染引擎进行渲染。

---

### **代码中的作用**

在你的代码中：

```javascript
const {nodes} = await useGLTF('./plugins/basic/htmls/model/model.gltf', {
    draco: true,
    decoderPath: './draco/',
});
```

- **`draco: true`**：告诉 `useGLTF`，加载的 GLTF 文件是经过 Draco 压缩的，需要在客户端进行解压缩。
- **`decoderPath: './draco/'`**：指定 Draco 解码器的路径，客户端需要加载解码器文件（通常是 `.js` 和 `.wasm` 文件）来完成解压缩。

---

### **性能影响**

1. **网络传输**：
    - 压缩后的 GLTF 文件更小，传输时间更短。
    - 这是 Draco 压缩的主要优势。

2. **客户端解压缩**：
    - 解压缩确实会在客户端带来一定的性能开销。
    - 对于现代设备，解压缩的开销通常较小，尤其是对于中小型模型。
    - 对于大型模型，解压缩的开销可能会稍微明显一些，但仍然远小于未压缩模型的加载时间。

---

### **总结**

- Draco 压缩是在模型制作阶段完成的，而不是在客户端代码中完成的。
- 客户端代码的作用是加载压缩后的 GLTF 文件，并使用 Draco 解码器对其进行解压缩。
- 虽然解压缩会带来一定的性能开销，但由于文件大小显著减小，整体加载时间通常会更快。
